# Development flow

For work that changes code, follow these steps in order:

1. Contracts - read `.agents/contracts.md`.
2. Tests - read `.agents/tests.md`.
3. Documentation - read `.agents/documentation.md`.
4. Code - read `.agents/code.md`.
5. Cleanup - read `.agents/cleanup.md`.

Complete one step at a time and never mix steps. Continue automatically from one
completed step to the next; do not stop for routine approval between steps. Stop
only when a genuine unresolved question or blocker requires user input.
Feedback keeps the work in the current step. If an earlier decision must change,
return to that step before continuing forward again.

## Living standards

The files in `.agents` are project memory. When the user states or changes a
development standard, update the appropriate file during the current step. Do
not leave the standard only in the conversation. Keep the recorded rule concise
and preserve its intent.

Organize instruction files by subject, not separate `Do` and `Don't` sections.
Keep a rule, its rationale, and its correct and incorrect examples together.
